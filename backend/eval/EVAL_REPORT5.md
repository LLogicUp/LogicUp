> 평가 일시: 2026-05-26
> 모델: `openai/gpt-oss-120b` (via Groq)
> 테스트 케이스: 11개 문제 × 최대 3레벨 = 총 26개 케이스 (에러 1건 제외 시 유효 25건)
> 평가 방식: **카테고리 분류 정확도** (Precision/Recall/F1) + **LLM-as-Judge 품질 평가**
> 변경사항: L2 프롬프트 수정 — `### 예시 (코드 인라인 대비)` → `### 힌트 (코드 없이 한 문장)`

## 총평

| 지표 | 값 | 평가 |
|------|-----|------|
| 카테고리 분류 평균 F1 | **0.633** | 양호 |
| 카테고리 분류 평균 Precision | **0.680** | 양호 |
| 카테고리 분류 평균 Recall | **0.620** | 양호 |
| LLM Judge 평균 품질 점수 | **4.32 / 5** | ✅ 전체 평가 중 최고 |
| JSON 형식 통과율 | **100%** | 우수 |
| 레벨 규칙 위반 건수 (재판정) | **3건** | ✅ 전체 평가 중 최소 |
| 에러 건수 | **1건** (c_null_pointer L2, TPM) | - |

**핵심 결론:**
- **L2 규칙 위반 해소**: `### 예시` 섹션 제거로 정답 코드 노출이 사라짐 → Judge 평균 4.32/5로 역대 최고
- **규칙 위반 3건으로 최소화**: 남은 위반은 전부 L1에서 오류 원인까지 설명하는 패턴
- **F1 소폭 하락 (0.653 → 0.633)**: c_null_pointer L2 TPM 에러 + algo_dfs_no_visit L1/L2 분류 후퇴 영향
- **py_index_error 지속 오분류**: `배열 범위 초과` / `오프바이원` 사용 — `리스트 인덱스 오류 (IndexError)` 미사용
- **algo_dfs_no_visit 카테고리 후퇴**: L1/L2에서 `스택 오버플로우`(증상) 사용, L3에서만 `DFS 방문 체크 누락`(근본 원인) 사용
