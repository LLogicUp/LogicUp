## 레벨 규칙 위반 분석

### 위반 건수: 8건 (유효 케이스 22건 중 36%)

| 레벨 | 위반 유형 | 빈도 |
|------|----------|------|
| L1 | 오류 부분 코드 스니펫 노출 | 4건 |
| L2 | 예시에 정답 코드 포함 | 3건 |
| L3 | explanation에 실제 언어 코드 삽입 | 1건 |

### 위반 패턴
L1 규칙 "오류 위치와 타입만 알려줄 것"에서 **오류 부분 코드를 백틱으로 표시**하는 행동이 반복됨.
현재 `prompts.py` L1 형식에 `**오류 부분**: 해당 코드를 백틱으로 감싸서 표시` 라고 명시되어 있어서  
LLM이 이를 따르는 것인데, **Judge는 이를 규칙 위반으로 판정**.

> **→ SYSTEM_PROMPT의 L1 지시문이 자기모순적**: 오류 부분 코드 표시를 요구하면서 동시에 코드 노출 금지 원칙과 충돌

## 문제 유형별 분류 성능

| 버그 유형 | 성능 | 분석 |
|-----------|------|------|
| 일반 C 런타임 에러 (printf, off-by-one, 무한루프) | 우수 (F1≈1.0) | 에러 로그와 패턴 명확 |
| 포인터/문자열 오류 | 보통 (F1≈0.67) | 연관 카테고리 추가 분류 경향 |

| 알고리즘 특화 버그 | 카테고리 불일치 (F1=0.0) | 일반 카테고리로 분류, 힌트 품질은 우수 |

## 개선 권고사항

### 1순위 — 프롬프트 수정 (즉시 적용 가능)

**`prompts.py` L1 지시문 수정**
```
# 현재 (자기모순)
"**오류 부분**: 해당 코드를 `백틱`으로 감싸서 표시"

# 수정안
"**오류 위치**: N번째 줄"
"**오류 타입**: 에러 유형만 서술 (코드 인용 금지)"
```

**`prompts.py` L2 지시문 수정**
```
# 추가할 내용
"올바른 코드 예시를 그대로 제시하지 말고, 잘못된 패턴과 올바른 패턴의 차이를 
추상적으로 설명할 것. 정답 코드 한 줄도 포함 금지."
```

### 2순위 — 테스트케이스 개선

- **`c_memory_leak`**: error_log에 `"valgrind: LEAK SUMMARY: 4 bytes lost"` 추가
- **`py_index_error`**: expected_categories를 `["리스트 인덱스 오류 (IndexError)"]`로 유지하되, 허용 동의어 목록 추가 검토
- **알고리즘 케이스**: expected_categories를 `["이분 탐색 범위 오류", "이분 탐색 조건 오류"]` 유지 또는 `["무한루프", "오프바이원 (off-by-one)"]`도 정답으로 허용하는 soft matching 도입

### 3순위 — 인프라

- **Rate limit 대응**: `run_eval.py`의 `time.sleep(0.5)` → `time.sleep(3)` 으로 변경
- 또는 429 발생 시 자동 재시도 로직 추가
