## 9차 평가 종합 비교

| 항목 | 6차 | 7차 | 8차 | 9차 |
|------|-----|-----|-----|-----|
| 카테고리 평균 F1 | 0.744 | 0.812 | 0.674 | **0.800** |
| 평균 Precision | 0.808 | 0.848 | 0.646 | **0.840** |
| 평균 Recall | 0.712 | 0.804 | 0.729 | **0.800** |
| LLM Judge 평균 점수 | 4.12 | 3.48 | 3.92 | **3.76** |
| 규칙 위반 건수 | 3건 | 8건 | 7건 | **10건** ❌ |
| API 에러 건수 | 0건 | 3건 | 2건 | **1건** |

**결론:**
- **F1 0.800으로 안정화**: 8차 회귀 복구, 7차(역대 최고 0.812)에 근접
- **`algo_dfs_no_visit` L2 개선**: 7차에서 0.0이었던 L2가 1.0 달성 — 전 평가 통틀어 처음
- **규칙 위반 10건 역대 최다**: L1 형식 준수 문제가 few-shot으로 해결되지 않음을 재확인
- **차기 개선 방향**:
  1. **L1 형식 문제** — few-shot 단일 예시 한계, 근본적 접근 필요 (예시 다양화 or 별도 시스템 구조)
  2. **`algo_binary_search` L3** — `이분 탐색` 전용 카테고리를 L3에서도 선택하도록 유도
  3. **`c_memory_leak`** — error_log 없이 탐지 불가 구조적 한계, 테스트 케이스 재설계 고려
  4. **`c_string_no_null` L1 JSON 에러** — 문자 배열 코드가 파싱 에러 유발, 재실행 시 간헐적 발생 가능
